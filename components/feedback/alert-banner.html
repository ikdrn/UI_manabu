設計の意図

なぜ4段階の重大度レベルがあるのか？
アラートの種類を「情報 < 成功 < 警告 < エラー」の4段階に分けることで、ユーザーはメッセージの緊急度を色だけで瞬時に判断できます。青は穏やかな情報、赤は緊急の問題と、信号機のような直感的なマッピングを利用しています。

左ボーダーによる視覚的カテゴリ分け
左端に太い色付きボーダー（border-left: 4px solid）を引くのは、アラートやカード型コンポーネントでよく使われるデザインパターンです。全体を塗りつぶすより控えめでありながら、ひと目で種類を区別できます。

永続表示 vs 閉じられるアラート
エラーアラートは閉じるボタンを省略し、問題が解決されるまで表示し続けるべきです。一方、成功通知はユーザーが確認したら不要になるため、閉じられるようにします。この使い分けが、ユーザーの混乱や重要な通知の見落としを防ぎます。

role="alert" と role="status" の使い分け
role="alert"はスクリーンリーダーに即座に読み上げられるため、緊急性の高い警告・エラーに適しています。一方、role="status"は控えめに通知され、情報や成功メッセージに使います。すべてにrole="alert"を使うと、ユーザーが通知疲れを起こします。

/* --- アラートの基本レイアウト --- */
.alert {
  /* display: flex → アイコン・テキスト・閉じるボタンを横並びにする。
     Flexboxは1次元（横or縦）のレイアウトに最適 */
  display: flex;

  /* align-items: flex-start → 子要素を上端に揃える。
     center にすると複数行テキストの場合にアイコンが
     縦中央に来てしまい、不自然に見える */
  align-items: flex-start;

  /* gap → アイコン・テキスト・ボタン間のスペース。
     marginで個別指定するより、gapの方がシンプルで保守しやすい */
  gap: 12px;

  padding: 12px 16px;
  border-radius: 8px;

  /* border-left: 4px solid → 左端に太い色付きボーダー。
     var(--alert-color) でバリアントごとに色を変える。
     CSSカスタムプロパティを使うことで、親のクラスを変えるだけで
     子要素の色もすべて連動して切り替わる */
  border-left: 4px solid var(--alert-color);

  /* 背景色もカスタムプロパティで管理 */
  background-color: var(--alert-bg);
  color: var(--alert-text);
}

/* --- CSSカスタムプロパティによるバリアント定義 ---
   カスタムプロパティ（CSS変数）の利点:
   ・色の定義が1箇所に集約されメンテナンスが容易
   ・新しいバリアントの追加が3行で完了
   ・子要素が var(--alert-color) を参照するだけで自動的に色が変わる */

.alert--info {
  --alert-color: #2563eb;   /* 青 — 情報、お知らせ */
  --alert-bg: #eff6ff;      /* 薄い青の背景 */
  --alert-text: #1e40af;    /* 濃い青のテキスト */
}

.alert--success {
  --alert-color: #16a34a;   /* 緑 — 成功、完了 */
  --alert-bg: #f0fdf4;
  --alert-text: #166534;
}

.alert--warning {
  --alert-color: #d97706;   /* 琥珀色 — 警告、注意 */
  --alert-bg: #fffbeb;
  --alert-text: #92400e;
}

.alert--error {
  --alert-color: #dc2626;   /* 赤 — エラー、問題 */
  --alert-bg: #fef2f2;
  --alert-text: #991b1b;
}

/* --- アイコン --- */
.alert__icon {
  /* flex-shrink: 0 → テキストが長くてもアイコンが縮まないようにする。
     デフォルトではflex子要素は縮小するため、明示的に固定する */
  flex-shrink: 0;
  width: 20px;
  height: 20px;
}

/* --- テキストエリア --- */
.alert__content {
  /* flex: 1 → 残りの横幅をすべて占有する。
     アイコンと閉じるボタンの間のスペースを最大限使う */
  flex: 1;
  min-width: 0; /* flexの子要素のオーバーフローを防ぐ */
}

/* --- 閉じるボタン --- */
.alert__dismiss {
  flex-shrink: 0;
  background: none;
  border: none;
  cursor: pointer;
  color: var(--alert-color);
  border-radius: 4px;
  transition: background-color 150ms;
}

.alert__dismiss:hover {
  /* 半透明の背景でホバーフィードバックを出す */
  background-color: rgba(0, 0, 0, 0.08);
}
// --- アラートの閉じる（dismiss）処理 ---

// querySelectorAll → ページ内のすべての閉じるボタンを取得
// '.alert__dismiss' というCSSセレクタに一致する要素をすべて選ぶ
document.querySelectorAll('.alert__dismiss').forEach(function(btn) {

  // addEventListener('click', ...) → クリックイベントを監視する。
  // ボタンが押されたら中の関数が実行される
  btn.addEventListener('click', function() {

    // closest('.alert') → ボタンから最も近い親の .alert 要素を探す。
    // これにより、どのアラートの閉じるボタンが押されたかを特定できる。
    // closest() は自分自身→親→祖父母...と上方向に検索する便利なメソッド
    var alert = btn.closest('.alert');
    if (!alert) return;

    // --- アニメーション付きで閉じる ---
    // 1. まず現在の高さを取得して max-height に設定
    //    （CSSトランジションは auto → 0 を補間できないため、
    //    具体的なpx値が必要）
    alert.style.maxHeight = alert.offsetHeight + 'px';

    // 2. ブラウザに現在の状態を描画させる（リフロー強制）
    //    これがないと、maxHeightの設定と dismissing クラスの追加が
    //    同じフレームで処理され、アニメーションが発生しない
    alert.offsetHeight; // リフローを強制するためのトリック

    // 3. dismissing クラスを追加してCSSアニメーションを開始
    alert.classList.add('alert--dismissing');

    // 4. アニメーション完了後にDOMから要素を削除する。
    //    setTimeout の 300ms は CSS transition の duration と合わせる。
    //    要素を非表示（display: none）ではなく完全に削除（remove）する
    //    ことで、DOMをクリーンに保つ
    setTimeout(function() {
      alert.remove();
    }, 300);
  });
});
