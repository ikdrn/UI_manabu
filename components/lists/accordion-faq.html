ネイティブ実装（details/summary）

UIデザインで最も大切なことは何ですか？
情報の優先順位を明確にすることです。画面内で「何が主役か」がひと目で分かるようにし、ユーザーが迷わず目的を達成できるよう導きます。
カラーパレットの選び方を教えてください
色に役割を持たせることが重要です。ブランド色・操作色・状態色・注意色を分け、同じ色に複数の意味を持たせないようにしましょう。
レスポンシブデザインの基本原則は？
モバイルファーストで設計し、min-widthメディアクエリで段階的に拡張します。コンテンツの優先度を決め、小さい画面でも重要な情報が見えるようにします。
アクセシビリティ対応は必須ですか？
はい。法的義務であるだけでなく、全ユーザーの体験を向上させます。キーボード操作、スクリーンリーダー対応、十分なコントラスト比が基本です。

カスタム実装（アニメーション付き・排他モード）

transform と opacity のみをアニメーションさせましょう。これらのプロパティはGPUで処理されるため、レイアウトの再計算が発生せず滑らかに動きます。width や height のアニメーションは避けてください。

max-heightを使った従来の方法は、実際の高さが分からないため値の推測が必要でした。grid-template-rows: 0fr → 1fr はコンテンツの自然な高さまで正確にアニメーションします。

FAQのように項目が多い場合は排他モードが有効です。全部開くと画面が長くなりすぎ、ユーザーが迷います。ただし、設定画面など複数を同時に確認したいケースでは非排他のほうが良いです。

可能ならネイティブの details/summary を使ってください。JSなしで動き、アクセシビリティも標準対応です。アニメーションや排他モードが必要な場合のみカスタム実装を検討します。

設計の意図

プログレッシブ・ディスクロージャー
すべての情報を一度に見せると認知負荷が高くなります。アコーディオンは「見出しで判断→興味があれば開く」という段階的な情報開示を実現します。

ネイティブ要素を優先する理由
details/summaryはブラウザ標準の要素で、JSなしで動作し、スクリーンリーダーも正しく読み上げます。車輪の再発明を避け、必要な場合のみカスタマイズしましょう。

コード解説

/* カスタムアコーディオンの開閉アニメーション */
.faq-panel {
  /* display: grid → grid-template-rowsでアニメーションするため */
  display: grid;
  /* 0fr → 高さ0（閉じた状態） */
  grid-template-rows: 0fr;
  /* transition → 開閉をなめらかにアニメーション */
  transition: grid-template-rows 400ms cubic-bezier(0.16, 1, 0.3, 1);
}

/* .open クラスが付いたら 1fr → コンテンツの自然な高さまで展開 */
.faq-item.open .faq-panel {
  grid-template-rows: 1fr;
}

/* 内側の要素に overflow: hidden が必須 */
.faq-panel-inner {
  /* overflow: hidden → 0frの時にコンテンツがはみ出さないようにする */
  overflow: hidden;
}

/* +/− アイコンの切り替え（CSSのみ） */
.faq-icon::before { width: 12px; height: 2px; } /* 横棒（常に表示） */
.faq-icon::after { width: 2px; height: 12px; }  /* 縦棒（回転で消える） */
.faq-item.open .faq-icon::after {
  /* 90度回転 → 縦棒が横棒と重なり「−」に見える */
  transform: translate(-50%, -50%) rotate(90deg);
}
/* 排他モード: 1つ開くと他が閉じる */
var faqItems = document.querySelectorAll('.faq-item');

faqItems.forEach(function(item) {
  var trigger = item.querySelector('.faq-trigger');

  trigger.addEventListener('click', function() {
    var isOpen = item.classList.contains('open');

    /* まず全項目を閉じる（排他モード） */
    faqItems.forEach(function(other) {
      other.classList.remove('open');
      other.querySelector('.faq-trigger')
        .setAttribute('aria-expanded', 'false');
    });

    /* クリックした項目が閉じていたら開く */
    if (!isOpen) {
      item.classList.add('open');
      trigger.setAttribute('aria-expanded', 'true');
    }
  });
});

実運用でのエッジケース

長い質問テキスト（折り返し確認）
レスポンシブデザインでブレークポイントの設計に困っています。モバイルファーストで考えるべきですか？
モバイルファーストが推奨されます。まず最小画面で必須の情報を整理し、大きい画面で追加要素を配置していきます。
長い回答テキスト（全文表示・スクロールなし）
回答が非常に長い場合は？
アコーディオン内のコンテンツが長くなる場合、スクロールバーを付けずに全文を表示するのが一般的です。ユーザーがスクロール位置を見失わないよう、開閉時にスムーズにスクロールする配慮も重要です。リスト、画像、コードブロックなど様々なコンテンツが入る可能性を考慮してパディングと行間を適切に設定しましょう。
