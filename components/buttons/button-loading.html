ボタン

ローディングボタン

ボタンをクリックした後、処理中であることをユーザーに伝えるローディング状態付きボタン。即座にフィードバックを返すことで、ユーザーの不安を取り除き、二重送信を防ぎます。

プレビュー

※ クリックすると2秒間ローディング状態になり、自動的に元に戻ります。

設計の意図

なぜ即座にフィードバックを返すのか？
ユーザーがボタンを押した後、画面に何も変化がないと「押せたのか？」「壊れたのか？」と不安になります。ローディング状態を表示することで「あなたの操作を受け付けました。今処理中です」と伝えることができます。ヤコブ・ニールセンの研究では、0.1秒以内の反応が「瞬時」と感じられるとされています。

二重送信の防止
決済や投稿などの操作で、ユーザーが「押せてないかも」と何度もクリックすると、同じ処理が複数回実行されてしまいます。ローディング中は pointer-events: none でクリックを無効化し、この問題を防ぎます。

ローディング状態 vs disabled状態の違い
disabled 属性は「この操作はまだ利用できません」を意味します。一方、ローディング状態は「操作を受け付けて処理中です」を意味します。目的が異なるため、見た目も使い分けます。ローディングではスピナーを表示し、テキストを「処理中...」に変えることで、待てば完了することを伝えます。

コード解説



<button type="button" class="btn" id="loading-btn" aria-busy="false">

  
  
  <span class="btn__spinner" aria-hidden="true"></span>

  
  <span class="btn__text">送信する</span>

</button>
/* === スピナーのアニメーション定義 ===
   @keyframes → CSSアニメーションの「動きの台本」を定義する。
   名前を付けて、animationプロパティから呼び出す */
@keyframes spin {
  /* from（= 0%）→ アニメーション開始時の状態 */
  0% {
    /* rotate(0deg) → 回転角度0度。まだ回っていない */
    transform: rotate(0deg);
  }
  /* to（= 100%）→ アニメーション終了時の状態 */
  100% {
    /* rotate(360deg) → 360度回転 = 1周。
       0→360の変化を繰り返すことで連続回転する */
    transform: rotate(360deg);
  }
}

/* === スピナー要素のスタイル === */
.btn__spinner {
  /* 正方形にして円の土台を作る */
  width: 14px;
  height: 14px;

  /* border → 円の「輪っか」を作る線。
     rgba(255,255,255,0.3) → 白の30%不透明度で薄い円を描く */
  border: 2px solid rgba(255, 255, 255, 0.3);

  /* border-top-color: transparent → 上辺だけ透明にする。
     これがスピナーの「切れ目」になる。
     回転すると、この切れ目が回って見える = ローディング表現 */
  border-top-color: transparent;

  /* border-radius: 50% → 正方形 → 完全な円に変形 */
  border-radius: 50%;

  /* animation の一括指定。各値の意味：
     spin     → 使用する @keyframes の名前
     0.8s     → 1回転に0.8秒かける（速すぎず遅すぎない速度）
     linear   → 等速で回転する（ease にすると不自然に速度が変わる）
     infinite → 永遠に繰り返す（ローディング中ずっと回る） */
  animation: spin 0.8s linear infinite;

  /* 通常時は非表示。ローディング中のみ表示する */
  display: none;
}

/* === ローディング状態のボタン === */
.btn--loading {
  /* pointer-events: none → マウスのクリック・ホバーを完全に無効化。
     HTMLの disabled属性を使わずにCSSだけでクリック不可にできる。
     ※ disabled だとフォーム送信から除外されるなど副作用があるため、
     ローディング中は pointer-events で制御するのがベター */
  pointer-events: none;

  /* opacity: 0.7 → 透明度を下げて「操作できない」ことを示す。
     完全に消す(0)のではなく、少し薄くすることで
     「まだ存在しているが、今は使えない」と伝える */
  opacity: 0.7;

  /* カーソル変更（pointer-eventsがnoneなので直接見えないが、
     CSSの一貫性のために指定） */
  cursor: not-allowed;
}

/* ローディング中だけスピナーを表示する */
.btn--loading .btn__spinner {
  /* display: inline-block → 非表示(none)から表示に切り替え。
     inline-block にすることでテキストと横並びになる */
  display: inline-block;
}
// ローディングボタンの動作制御

// getElementById → HTMLのid属性でDOM要素を取得する
const btn = document.getElementById('loading-btn');
// querySelector → CSSセレクタで子要素を取得する
const btnText = btn.querySelector('.btn__text');

// addEventListener → ボタンのクリックイベントを監視する
btn.addEventListener('click', function () {

  // --- ローディング開始 ---

  // classList.add → 要素にCSSクラスを追加する。
  // 'btn--loading' を付けることで、CSSのローディングスタイルが適用される
  btn.classList.add('btn--loading');

  // setAttribute → HTML属性の値を変更する。
  // aria-busy="true" でスクリーンリーダーに「処理中」と伝える
  btn.setAttribute('aria-busy', 'true');

  // textContent → 要素のテキストを書き換える。
  // ユーザーに「処理中」であることをテキストでも伝える
  btnText.textContent = '処理中...';

  // --- 2秒後にローディング解除（デモ用） ---

  // setTimeout → 指定したミリ秒後に関数を実行する。
  // 2000ミリ秒 = 2秒。実際のアプリではAPIのレスポンスを待つ
  setTimeout(function () {

    // classList.remove → 要素からCSSクラスを削除する。
    // ローディングスタイルが解除され、通常状態に戻る
    btn.classList.remove('btn--loading');

    // aria-busy を false に戻す → 「処理が終わった」と伝える
    btn.setAttribute('aria-busy', 'false');

    // テキストを元に戻す
    btnText.textContent = '送信する';

  }, 2000);  // 2000ミリ秒 = 2秒後に実行
});

実運用でのエッジケース

連打対策（素早く何度もクリック）

pointer-events: none により、ローディング中のクリックは無視されます。ただし、classList.add が実行される前の極めて短い時間に2回目のクリックが入る可能性があるため、実運用ではJavaScript側でもフラグ変数（isLoading）を使って二重実行を防ぎます。

実行回数: 0
タイムアウト対策（ネットワーク遅延）

実際のアプリケーションでは、通信が永遠に終わらない可能性があります。一定時間（例: 10秒）経っても応答がない場合は、ローディングを解除してエラーメッセージを表示するべきです。ユーザーを無限に待たせないことが重要です。
