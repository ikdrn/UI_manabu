フォーム入力

テキストエリア（文字数カウンター付き）

複数行テキスト入力に文字数カウンターと自動リサイズ機能を組み合わせたコンポーネント。入力量の目安をリアルタイムで伝え、ユーザーが安心して書ける環境を作ります。

プレビュー

マークダウン記法は使用できません 0 / 200
文字数の上限を超えています。200文字以内にしてください。

設計の意図

文字数制限はUXガイダンスである
カウンターは「あとどれくらい書けるか」を可視化し、ユーザーの期待値を設定します。制限がないと「どこまで書いていいのか」不安になり、逆に長大なテキストが送られるリスクも増えます。

自動リサイズ vs 固定高さ
固定高さのテキストエリアでは、長い文章がスクロール内に隠れてしまい全体を見渡せません。自動リサイズは「書いた分だけ広がる」ため、より自然な筆記体験を提供します。ただし max-height で上限を設け、ページレイアウトが崩壊しないようにします。

カウンター配置は右下が慣習
テキストの読み書きは左上から始まり、右下へ進みます。カウンターを右下に置くことで、入力完了時に自然と視界に入ります。左下にはヘルパーテキストを配置して役割を分けます。

maxlength属性 vs JavaScriptによる制限
maxlength属性はブラウザがネイティブに入力を制限します。200文字を超える入力が物理的にできなくなるため安全ですが、「なぜ入力できないのか」ユーザーに伝わりにくい欠点があります。JS制限なら超過を許可しつつ警告を出せるので、よりフレンドリーです。このデモではJS制限を採用しています。

コード解説

<!-- form-group → ラベル・入力・ヘルパーをまとめる容器 -->
<div class="form-group">

  <!-- label要素 → for属性でtextareaと紐付ける。
       クリックするとテキストエリアにフォーカスが移る -->
  <label class="form-label" for="comment">
    コメント
    <span class="form-label__required" aria-label="必須">*</span>
  </label>

  <!-- textarea要素 → 複数行のテキスト入力欄。
       input要素と違い、改行を含む長文を入力できる。

       【maxlength属性を使わない理由】
       maxlength="200" を付けると、ブラウザが200文字で入力を
       強制的にカットする。しかし、ユーザーは「なぜ途中で止まるのか」
       分からず困惑する。代わりにJSで超過を検知し、
       警告メッセージを表示する方がフレンドリー。

       aria-describedby → スクリーンリーダーに補足情報を伝える。
       複数IDをスペース区切りで指定でき、ヘルパーテキスト・
       カウンター・エラーメッセージの3つを関連付ける -->
  <textarea
    id="comment"
    class="textarea"
    placeholder="ご意見・ご感想をお聞かせください"
    aria-describedby="comment-helper comment-counter comment-error"
  ></textarea>

  <div class="textarea-footer">
    <span id="comment-helper" class="form-helper">
      マークダウン記法は使用できません
    </span>

    <!-- aria-live="polite" → 内容が更新されたとき、
         スクリーンリーダーが「次の切れ目」で読み上げる。
         "assertive" は即座に割り込むため、
         毎キーストロークでは煩わしくなる。
         aria-atomic="true" → 一部だけでなく要素全体を
         読み上げ直す（「120 / 200」全体を伝える） -->
    <span
      id="comment-counter"
      class="char-counter"
      aria-live="polite"
      aria-atomic="true"
    >0 / 200</span>
  </div>

  <!-- role="alert" → エラー表示時にスクリーンリーダーが
       即座に読み上げる（aria-live="assertive"相当） -->
  <span id="comment-error" class="form-error" role="alert">
    文字数の上限を超えています。200文字以内にしてください。
  </span>
</div>
.textarea {
  /* resize: none → ユーザーによる手動リサイズを無効化する。
     自動リサイズをJSで制御するため、手動リサイズと競合しないようにする。
     【代替案】resize: vertical にすれば縦方向のみ手動リサイズ可能。
     自動リサイズを使わない場合は vertical が親切 */
  resize: none;

  /* min-height → テキストエリアの最小高さ。
     空の状態でも「ここに複数行書ける」と伝わるサイズにする。
     1行だけの入力欄と視覚的に区別するために重要 */
  min-height: 120px;

  /* max-height → 自動リサイズの上限値。
     これがないとテキストエリアが際限なく伸び続け、
     ページの他のコンテンツが押し下げられてしまう。
     上限を超えた分はスクロールで閲覧する */
  max-height: 300px;

  /* overflow-y: auto → 内容がmax-heightを超えたときだけ
     スクロールバーを表示する。
     "scroll" だと常にスクロールバーが見えてしまう */
  overflow-y: auto;

  width: 100%;
  padding: 12px;
  font-size: 0.875rem;
  font-family: inherit; /* ← ブラウザデフォルトのmonospace を上書き */
  line-height: 1.6;
  border: 1px solid #d1d5db;
  border-radius: 8px;
  transition: border-color 150ms, box-shadow 150ms;
}

/* フォーカス時 → 入力中であることを視覚的に示す */
.textarea:focus {
  outline: none;
  border-color: #3b82f6;
  /* box-shadow でフォーカスリングを表現する。
     outline より角丸に沿った見た目になる */
  box-shadow: 0 0 0 3px hsla(222, 80%, 50%, 0.15);
}

  box-shadow: 0 0 0 3px hsla(0, 80%, 50%, 0.15);

// ===================================================================
// テキストエリア — 自動リサイズ＋文字数カウンター
// ===================================================================

const textarea = document.getElementById('comment');
const counter = document.getElementById('comment-counter');
const errorMsg = document.getElementById('comment-error');
const MAX_LENGTH = 200;

// --- 警告しきい値：残り20%（160文字）を超えたら警告色にする ---
const WARNING_THRESHOLD = Math.floor(MAX_LENGTH * 0.8);

// === 自動リサイズ関数 ===
// textareaのscrollHeight（内容の実際の高さ）に合わせて
// 要素の高さを動的に変更する
function autoResize() {
  // 1. まずheightを'auto'にリセットする。
  //    これをしないと、前回設定したheightが残り、
  //    scrollHeightが正しく計算されない（小さくなれない）
  textarea.style.height = 'auto';

  // 2. scrollHeight → 内容全体の高さ（スクロールしないと
  //    見えない部分も含む）をpxで取得できる
  //    これをheightに設定することで、内容に合わせて伸縮する
  textarea.style.height = textarea.scrollHeight + 'px';
}

// === 文字数カウンター更新関数 ===
function updateCounter() {
  // --- 文字数の取得 ---
  // 【注意】絵文字のカウント問題：
  // string.length は UTF-16 コード単位で数える。
  // 例："😀".length === 2（サロゲートペア）
  // 例："👨‍👩‍👧‍👦".length === 11（ZWJシーケンス）
  //
  // より正確に数えるには [...str].length（スプレッド構文）を使う。
  // これはUnicodeコードポイント単位で数えるため、
  // "😀" → 1 になる。
  // ただしZWJシーケンス（家族絵文字等）は複数カウントされる。
  //
  // 完全な「見た目の文字数」を得るには
  // Intl.Segmenter を使う（モダンブラウザ対応）
  const charCount = [...textarea.value].length;

  // --- カウンター表示を更新 ---
  counter.textContent = charCount + ' / ' + MAX_LENGTH;

  // --- 状態に応じてクラスを切り替え ---
  // まず全状態クラスをリセット
  counter.classList.remove('char-counter--warning', 'char-counter--over');
  textarea.classList.remove('textarea--over');
  errorMsg.classList.remove('form-error--visible');

  if (charCount > MAX_LENGTH) {
    // 超過状態：赤いカウンター＋赤いボーダー＋エラーメッセージ
    counter.classList.add('char-counter--over');
    textarea.classList.add('textarea--over');
    errorMsg.classList.add('form-error--visible');
  } else if (charCount > WARNING_THRESHOLD) {
    // 警告状態：黄色いカウンター
    counter.classList.add('char-counter--warning');
  }
}

// === イベントリスナーの登録 ===

// 【inputイベント vs changeイベント】
// - input → キーストロークごとに発火する。
//   文字を1つ打つたびにカウンターが更新される。
//   ペースト、ドラッグ＆ドロップ、音声入力でも発火する。
// - change → フォーカスが外れたとき（blur）に発火する。
//   リアルタイム更新には向かない。
//
// 文字数カウンターはリアルタイム性が重要なので input を使う。
textarea.addEventListener('input', function () {
  updateCounter();
  autoResize();
});

// --- 初期化 ---
// ページ読み込み時に一度実行し、
// ブラウザの自動入力などで初期値がある場合に備える
updateCounter();
autoResize();

実運用でのエッジケース

長文ペースト

テキストエリアに200文字を超える文章をペーストしてみてください。maxlength属性を使わないため入力は許可されますが、カウンターが赤くなりエラーメッセージが表示されます。送信ボタン側でバリデーションを行い、超過時は送信を無効化します。

絵文字の文字数カウント

このデモでは [...str].length（スプレッド構文）を使い、Unicodeコードポイント単位でカウントしています。基本的な絵文字（😀）は1文字、家族絵文字（👨‍👩‍👧‍👦）はZWJで結合された複数コードポイントのため複数文字としてカウントされます。厳密な「見た目の文字数」が必要なら Intl.Segmenter の使用を検討してください。

高速タイピング

inputイベントはキーストロークごとに発火するため、高速タイピングでもカウンターは追従します。パフォーマンスが懸念される場合は requestAnimationFrame でデバウンスできますが、200文字程度の処理なら不要です。
