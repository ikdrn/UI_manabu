レスポンシブテーブル

画面幅が狭い時にテーブルを見やすくする3つの戦略。データの性質に応じて使い分けます。

プレビュー

戦略1

横スクロール

テーブル全体をスクロール可能なコンテナで囲む。最もシンプルな手法。

カードリフロー

モバイルで各行をカード型に変換。data-label属性で列名を表示。640px以下で変化します。

優先カラム

画面幅に応じて優先度の低い列を非表示にする。768px以下で「low」、480px以下で「medium」が消えます。

設計の意図

横スクロール — 最もシンプルで安全
テーブルの構造を壊さないため、比較が必要なデータ（数値の比較など）に適しています。ユーザーが横スクロールできることに気づくよう、影やスクロールバーで示唆するとより親切です。

カードリフロー — 詳細表示に最適
各行が独立したエンティティ（人、注文、製品など）の場合に有効です。data-label属性でCSSの content: attr(data-label) を使い、各セルの前にヘッダー名を表示します。

優先カラム — 段階的な情報開示
全列が同じ重要度ではない場合、優先度を付けて画面幅に応じて非表示にします。「詳細を表示」ボタンと組み合わせると、非表示の列を展開できます。

コード解説

<!-- 戦略1: 横スクロール → ラッパーでoverflow-x:auto -->
<div class="table-scroll-wrapper">
  <table class="resp-table">...</table>
</div>

<!-- 戦略2: カードリフロー → data-labelでヘッダー名を指定 -->
<table class="resp-table table-card">
  <thead>
    <tr><th>名前</th><th>役職</th></tr>
  </thead>
  <tbody>
    <tr>
      <!-- data-label → モバイル時にCSSで列名として表示 -->
      <td data-label="名前">田中太郎</td>
      <td data-label="役職">マネージャー</td>
    </tr>
  </tbody>
</table>

<!-- 戦略3: 優先カラム → data-priorityで重要度を指定 -->
<table class="resp-table table-priority">
  <thead>
    <tr>
      <th>名前</th>
      <!-- data-priority="low" → 768px以下で非表示 -->
      <th data-priority="low">住所</th>
      <!-- data-priority="medium" → 480px以下で非表示 -->
      <th data-priority="medium">電話</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>田中太郎</td>
      <td data-priority="low">東京都</td>
      <td data-priority="medium">090-xxxx</td>
    </tr>
  </tbody>
</table>
/* === 戦略1: 横スクロール === */
.table-scroll-wrapper {
  overflow-x: auto;                 /* 横にはみ出したらスクロール */
  -webkit-overflow-scrolling: touch; /* iOSで慣性スクロール有効化 */
}

/* === 戦略2: カードリフロー === */
@media (max-width: 640px) {
  .table-card thead {
    /* ヘッダーを視覚的に隠す（display:noneだとスクリーンリーダーも読めなくなる） */
    position: absolute;
    width: 1px; height: 1px;
    clip: rect(0, 0, 0, 0);
    overflow: hidden;
  }

  .table-card tbody tr {
    /* 各行をブロック要素（カード）に変換 */
    display: block;
    border: 1px solid var(--color-neutral-200);
    border-radius: 8px;
    margin-bottom: 12px;
  }

  .table-card tbody td {
    /* 各セルをflexで横並び：ラベル | 値 */
    display: flex;
    justify-content: space-between;
  }

  /* data-label の値を::beforeで表示 */
  .table-card tbody td::before {
    content: attr(data-label);
    font-weight: 600;
  }
}

/* === 戦略3: 優先カラム === */
@media (max-width: 768px) {
  /* 優先度「低」の列を隠す */
  .table-priority [data-priority="low"] {
    display: none;
  }
}

@media (max-width: 480px) {
  /* 優先度「中」の列も隠す */
  .table-priority [data-priority="medium"] {
    display: none;
  }
}

実運用でのエッジケース

戦略の選び方

横スクロール：列間の比較が重要なデータ（売上表、スプレッドシート風）

カードリフロー：各行が独立した情報（ユーザー一覧、注文履歴）

優先カラム：列に明確な優先順位がある場合（主要情報 + 補助情報）
