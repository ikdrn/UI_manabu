モーダル

確認ダイアログ

削除やキャンセルなど、取り消せない操作の前にユーザーに確認を求めるダイアログ。HTML標準の<dialog>要素とshowModal()を使い、アクセシブルかつ堅牢に実装します。

プレビュー

⚠

この項目を削除しますか？

この操作は取り消せません。削除された項目は復元できなくなります。

設計の意図

なぜ<dialog>要素を使うのか？
HTML標準の<dialog>要素は、showModal()でモーダル表示すると自動的にフォーカストラップ（Tab移動がダイアログ内に限定される）と、Escapeキーでの閉じる機能を提供します。これをdivで自前実装すると大量のJavaScriptが必要になり、アクセシビリティの漏れが起きやすくなります。

::backdropの役割
::backdrop疑似要素は、showModal()で開いた時にブラウザが自動生成する背景レイヤーです。これにより、ダイアログの背後のコンテンツが操作できなくなり、ユーザーの注意をダイアログに集中させます。

フェード＋スケールのアニメーション
scale(0.95)から1への変化は「ダイアログが手前に飛び出す」感覚を与えます。突然の出現よりも自然で、ユーザーが「何かが起きた」ことを認識しやすくなります。

危険な操作は右側に赤いボタン
「削除する」ボタンを赤くすることで、ユーザーに「これは慎重に判断すべき操作だ」と警告します。キャンセルを左に置くことで、手が滑って削除を押すリスクを下げます。

コード解説

<!-- dialog要素 → HTML標準のモーダルダイアログ -->
<!-- open属性は使わず、JavaScriptのshowModal()で開く -->
<dialog id="confirmDialog" class="confirm-dialog">

  <div class="confirm-dialog__content">
    <!-- 警告アイコン → 視覚的に「注意が必要」と伝える -->
    <div class="confirm-dialog__icon">⚠</div>

    <!-- タイトル → 何が起きるかを簡潔に伝える -->
    <h3 class="confirm-dialog__title">
      この項目を削除しますか？
    </h3>

    <!-- 補足メッセージ → 操作の影響を説明 -->
    <p class="confirm-dialog__message">
      この操作は取り消せません。
    </p>
  </div>

  <!-- ボタンエリア -->
  <div class="confirm-dialog__actions">
    <!-- キャンセル → close()でダイアログを閉じる -->
    <button type="button" class="confirm-dialog__btn">
      キャンセル
    </button>
    <!-- 削除 → 危険操作なので赤いボタン -->
    <button type="button"
            class="confirm-dialog__btn confirm-dialog__btn--danger">
      削除する
    </button>
  </div>
</dialog>

<!-- ダイアログを開くトリガーボタン -->
<button type="button" onclick="dialog.showModal()">
  項目を削除する
</button>
/* dialog要素のデフォルトスタイルをリセット */
.confirm-dialog {
  /* border: none → ブラウザデフォルトの枠線を消す */
  border: none;
  border-radius: 12px;
  padding: 0;
  max-width: 420px;
  width: 90%;
  background: #fff;

  /* box-shadow → 強めの影でダイアログを「浮かせる」 */
  box-shadow: 0 20px 60px rgba(0, 0, 0, 0.3);

  /* animation → 開くときにフェード+スケールで登場 */
  animation: dialog-enter 200ms ease-out;
}

/* 登場アニメーション */
@keyframes dialog-enter {
  from {
    opacity: 0;
    /* scale(0.95) → 少し小さい状態からスタート */
    transform: scale(0.95) translateY(-10px);
  }
  to {
    opacity: 1;
    transform: scale(1) translateY(0);
  }
}

/* ::backdrop → showModal()で自動生成される背景 */
.confirm-dialog::backdrop {
  /* 半透明の黒で背景を暗くする */
  background: rgba(0, 0, 0, 0.5);
  animation: backdrop-fade 200ms ease-out;
}

/* 危険操作ボタン */
.confirm-dialog__btn--danger {
  background: #ef4444;
  color: white;
  border-color: #ef4444;
}

.confirm-dialog__btn--danger:hover {
  /* より濃い赤で「押そうとしている」ことを強調 */
  background: #dc2626;
}
// dialog要素を取得
const dialog = document.getElementById('confirmDialog');

// showModal() → モーダルとして開く
// show()との違い：showModal()はbackdropを表示し、
// 背景の操作をブロックし、Escapeキーで閉じられる
dialog.showModal();

// close() → ダイアログを閉じる
dialog.close();

// 背景クリックで閉じる処理
dialog.addEventListener('click', (e) => {
  // e.target === dialog → ダイアログ自体がクリックされた
  // （中身ではなく背景部分がクリックされた場合）
  if (e.target === dialog) {
    dialog.close();
  }
});

// closeイベント → ダイアログが閉じた後の処理
dialog.addEventListener('close', () => {
  // dialog.returnValue → どのボタンで閉じたかを取得
  console.log('ダイアログが閉じました');
});

実運用でのエッジケース

長いメッセージテキスト

メッセージが長くなる場合、ダイアログの高さが自動的に伸びます。max-heightとoverflow-y: autoを設定してスクロール可能にすることも検討してください。

キーボード操作

showModal()を使うと、Escapeキーで自動的に閉じます。また、フォーカスがダイアログ内に閉じ込められるため、Tabキーでダイアログ外の要素に移動できません。

複数ダイアログの重なり

showModal()で開いたダイアログの上にさらにshowModal()で別のダイアログを開くと、新しいダイアログが最前面に表示されます。ただし、UXの観点からダイアログの2重表示は避けるべきです。
